# سوالف v45 — إصلاح رجوع ربط Claude Code إلى الإعدادات

هذه **حزمة إصلاح صغيرة فوق v44** وليست تحديثًا مستقلًا من الصفر.

## المشكلة

نسخة v44 أعادت معالج زر «ربط المحرك» القديم في `js/app.js`، فكان يفتح الإعدادات كل مرة، حتى في النسخة المحلية على `127.0.0.1:4781` وبعد حفظ مفتاح OpenRouter.

## الملفات

- `js/app.js` — يعيد فحص الاتصال الفعلي، مع حفظ تفويض المهمة الواحدة من v43.
- `index.html` — تحديث رابط app.js إلى v45 مع إبقاء واجهة v44 وأزرار طي الهيستوري.
- `sw.js` — نسخة كاش جديدة shell-v45 لتجاوز نسخة JavaScript القديمة.
- `tests/coding-connection-regression.test.mjs` — اختبار يمنع رجوع المشكلة.

## تركيب تحديث v45

1. **خذ نسخة احتياطية** من مشروع سوالف الحالي.
2. أغلق سوالف المحلي وأي نافذة تستعمله.
3. فك ZIP في جذر مشروع سوالف (نفس مجلد `package.json`) ثم وافق على **استبدال الملفات الثلاثة المتطابقة**. اترك بقية ملفات المشروع كما هي.
4. شغّل `Start-Sowalif.cmd` مجددًا، وافتح `http://127.0.0.1:4781/`.
5. اضغط `Ctrl+Shift+R`، ثم ادخل قسم «الشغل»، واختر Claude Code واضغط «ربط المحرك».
6. إذا المفتاح محفوظ والخدمة جاهزة ستظهر رسالة نجاح «Claude Code جاهز على الكمبيوتر»؛ وإذا Docker غير جاهز فستظهر رسالة واضحة بدل إعادة فتح الإعدادات.

**إذا كنت تستخدم Sowalif.exe بدل Start-Sowalif.cmd،** فالتعديلات على المشروع لا تُحدّث البرنامج المبني حتى تعيد بناء نسخة ويندوز وتشغّل نسخة EXE الجديدة.

لا تمسح بيانات الموقع، ولا تدخل مفتاح OpenRouter مرة ثانية إذا كان محفوظًا.

## فحص المطور

من نافذة PowerShell داخل مجلد المشروع:

```powershell
node --test tests/coding-connection-regression.test.mjs
```

تم فحص منطق التوصيل والملفات محليًا؛ لم يتم تشغيل اتصال API فعلي بمفتاحك الخاص. **وجود المفتاح محفوظًا لا يعني جاهزية Docker أو المحرك**.
