# إصلاح معالجة مرفقات سوالف — إصدار v40

## ما أُصلح

- **ZIP:** منع الملفات غير المدعومة من استهلاك حصة فك الضغط قبل المستندات المهمة، مع الاحتفاظ بجرد الأعضاء وحالة كل ملف.
- **ZIP:** إذا تعذّر فك عضو تالف أو فشل التحقق من CRC، تُسجل حالة هذا العضو ويستمر استخراج الأعضاء السليمة بدل إلغاء قراءة الأرشيف كله.
- **ZIP:** إعادة قراءة ذاكرات نصية قديمة للأرشيفات مرة واحدة عند توفر الملف الأصلي، بدل إعادة استخدام فهرس أسماء فقط.
- **PDF:** إرسال معاينة بصرية من الصفحات الأصلية للنماذج الداعمة للصور في الملفات القصيرة (حتى صفحتين)، حتى لو كان النص أصلاً قابلًا للاستخراج. هذا مهم للجداول والمتجهات والتواقيع والخانات الفارغة.
- **PDF:** دعم أداة `view_document_page` عند وجود نموذج يدعم الأدوات والرؤية؛ يمكن فتح صفحة محددة من PDF مباشر أو عضو PDF داخل ZIP (بمساره الكامل). حدّ مرئي قدره ست صفحات عبر الأداة في كل رد.
- **PDF:** للملفات الطويلة تكون المعاينات البصرية محددة ولا تُعامل معاينة صفحة أو صفحتين كقراءة بصرية كاملة.
- **التحديث:** زيادة إصدار الملفات المحملة إلى v40 وتحديث Service Worker لتجنب بقاء إصدار قديم في الكاش.

## خطوات التطبيق على المشروع الأصلي (وليس على ملف exe)

1. أغلق سوالف بالكامل، ثم خذ **نسخة احتياطية** من المشروع الأصلي، واحتفظ بنسخة من مجلد `js` والملفين `index.html` و`sw.js`.
2. فكّ هذا ZIP **داخل المجلد الرئيسي للمشروع** مع السماح باستبدال الملفات المتطابقة. يجب أن يصبح `js/chat.js` في مساره الأصلي، ولا تنقل مجلد `js` داخل `js` آخر.
3. لتجربة نسخة المتصفح المحلية: شغّل سوالف بالطريقة المعتادة وأعد تحميل الصفحة بعد تحديثها.
4. لنسخة Windows المعبأة في `Sowalif.exe`: إن كنت تشغّل النسخة المبنية، يلزم إعادة البناء **من المصدر** على Windows عبر `npm run desktop:build -- --zip` بعد التأكد من وجود متطلبات البناء. مجرد نسخ ملفات المصدر لا يغير `exe` القديم.
5. لنسخة GitHub Pages: ارفع الملفات المُعدّلة لمستودع الموقع وانشرها ثم افتح صفحة سوالف مجددًا. لا تنشر أي `.env` أو أسرار.
6. اختبر PDF عربيًا بجدول، وملف ZIP مختلطًا يضم PDF وDOCX وصورًا وملفات غير مدعومة. استخدم نموذجًا يدعم الرؤية والأدوات لرؤية الصفحات بالأداة.
7. إذا كان مرفق ZIP محفوظًا في محادثة قديمة ولم يبقَ الأصل على جهازك أو في حساب التخزين، يجب **إعادة إرفاق الأصل**؛ لا يستطيع الكود استعادة محتوى مفقود من نص الفهرس وحده.

## حدود التحقق

- نجح تشغيل 207 اختبارات من أصل 211 في بيئة Node.js المتاحة، مع تجاوز اختبار واحد وعدم تمكن 3 مجموعات اختبار من البدء بسبب فقد ملفات تبعية `fake-indexeddb` أثناء التثبيت. هذه ليست اختبارات فشلت بعد تشغيلها، لكنها غير متحققة هنا.
- لم تتوفر نسخة `حافظة ai.zip` الأصلية من المستخدم، لذلك لم نتحقق من تنسيق الضغط والأعضاء الـ34 الفعلية؛ التشخيص اعتمد على الكود وسلوك الرد ومختبرات صناعية.
- لم يتوفر تشغيل Electron على Windows أو وصول فعلي لمفاتيح المزوّد، ولذلك لم يتم إثبات نجاح القراءة البصرية المدفوعة على المزوّد أو نسخة Windows النهائية.
- الملف الأصلي PDF «نموذج 5-1.pdf» اختُبر في محرك PDF.js وتبيّن أنه صفحة واحدة وبها 61 عنصرًا نصيًا ولا يحتوي على عمليات رسم صور مضمنة؛ هذا يفسر لماذا كان مسار استخراج النص لا يعرض شكل الصفحة.

ملاحظة: قراءة PDF بصريًا قد تزيد الاستهلاك لدى مزوّد النموذج. تبقى الملفات الكبيرة والأرشيفات المحمية أو ذات التنسيقات غير المدعومة خاضعة لحدود المتصفح والنموذج.
