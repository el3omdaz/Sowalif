# سوالف v43 — خيار التفويض التلقائي أثناء تنفيذ المهمة

## ما الذي تغير؟
أضيف في قسم «الشغل» خيار **«السماح تلقائيًا لهذه المهمة»**.

- **الوضع الافتراضي:** يظل يسألك قبل أوامر الطرفية (Bash وغيرها حسب المحرك).
- **إذا فعّلت الخيار:** ستظهر نافذة تأكيد واحدة، ويُسمح للأوامر التي كانت تحتاج موافقتك خلال **المهمة الحالية فقط**. بعد بدء المهمة، يُلغى تحديد الخيار تلقائيًا؛ ولا يُحفظ كتفضيل دائم.
- **النطاق:** المحرك يعمل داخل حاوية Docker محدودة. هذا ليس تفويضًا بالتحكم في نظام ويندوز بكامله. لكن الأمر قد يعدّل أو يحذف ملفات المشروع المربوط فعليًا من ويندوز، وقد يتصل بالإنترنت أو يستخدم معلومات متاحة داخل الحاوية. استخدمه فقط مع مشاريع موثوقة وبعد أخذ نسخة احتياطية.
- استمرار فحوص مسارات أدوات الملفات وقيود الحاوية؛ هذا الخيار لا يغير تلك القيود.

## التثبيت على نسخة السؤالوف المحلية
1. أغلق تطبيق سوالف تمامًا، وليس فقط النافذة المخفية قرب الساعة، وأوقف الخدمة المحلية إن كانت تعمل.
2. خذ نسخة احتياطية من مجلد المشروع.
3. فك ZIP، وانسخ **الملفات والمجلدات التي بداخله** إلى مجلد المصدر الرئيسي لسوالف، مع استبدال الملفات المتطابقة. لا تنسخ مجلدًا حاويًا إضافيًا.
4. من PowerShell داخل مجلد سوالف الرئيسي نفّذ:

   ```powershell
   npm run agent:setup
   ```

   **مهم:** هذا يبني بيئة Docker الجديدة التي تحتوي `worker.mjs` المعدل؛ مجرد نسخ ملفات الواجهة لا يفعّل الإذن التلقائي.
5. إذا تستخدم النسخة المحلية عبر `Start-Sowalif.cmd`، أعد تشغيل الخدمة ثم افتح سوالف.
6. إذا تستخدم `Sowalif.exe`، أعد بناء نسخة ويندوز من المصدر المعدل:

   ```powershell
   npm run desktop:build -- --zip
   ```

   شغّل **النسخة الجديدة** من `desktop/dist`، وليس الاختصار الذي يفتح نسخة قديمة. مجلد إصدار Windows يحتوي الملفات مجتمعة.

## كيف تستخدمه؟
1. افتح «الشغل» واختر Claude Code أو محركًا آخر مدعومًا.
2. قبل إرسال الطلب، فعّل مربع «السماح تلقائيًا لهذه المهمة» بجانب محرك البرمجة.
3. اقرأ تحذير التفويض ثم اختر «موافق» إذا كانت هذه المهمة موثوقة.
4. أرسل الطلب. لن تظهر الموافقات الفردية المعتادة أثناء تنفيذ هذه المهمة. مهمة جديدة = قرار جديد.

## الاختبارات والملاحظات
- اختبارات مسار الموافقات المحلية وحصرها في المهمة نجحت.
- لا يوجد اختبار تشغيل فعلي مدفوع على مفتاح OpenRouter الخاص بك أو على نسخة Windows النهائية في هذه البيئة.
- تشغيل كل اختبارات المشروع هنا أظهر 209 نجاحات، و5 إخفاقات غير متعلقة بالتفويض (اثنان في اختبارات ZIP الموجودة في المشروع وثلاثة بسبب عدم تثبيت fake-indexeddb)، واختبارًا متجاوزًا. اختبارات التفويض ومسار الخادم المستهدف نجحت.

## ملفات التحديث
`index.html`, `style.css`, `sw.js`, `js/app.js`, `js/local-agent.js`, `server/local-agent/server.mjs`, `server/local-agent/worker.mjs`, `server/local-agent/agent-policy.mjs`.

الاختبارات المضافة في `tests/` اختيارية ولا تحتاجها النسخة المبنية للتشغيل.
